Notas del mockup

Qué se resolvió visualmente

  • Un único botón «Registrar ▾» en el shell con seis tipos; el tipo se preselecciona al lanzar desde una ficha y el caso queda fijado y bloqueado.
  • El panel lateral no navega: se abre sobre la vista de origen, conservando el contexto.
  • Alta y edición comparten descriptor; cambia el modo y el verbo HTTP.
  • La visibilidad por capacidad se muestra en dos roles reales del sistema (especialista con permiso parcial y lector).

Contrato del descriptor (ejemplo)

Forma mínima que el equipo debe leer para generar el formulario de demanda. El resto de entidades repite la misma forma. 

{
  "entidad": "demanda",
  "modo": "alta",
  "endpoints": { "alta": "POST /api/v1/demandas", "edicion": "PATCH /api/v1/demandas/{id}" },
  "capacidad": "demanda:crear",
  "contexto": {
    "caso_id": { "origen": "ficha", "fijado": true, "obligatorio": true },
    "alerta_id": { "origen": "ficha", "obligatorio": false }
  },
  "campos": [
    { "name": "problema_3p", "label": "Problema (3P)", "tipo": "texto_largo",
      "obligatorio": true, "max": 2000, "ayuda": "Qué ocurre y a quién afecta." },
    { "name": "propuesta_3p", "label": "Propuesta (3P)", "tipo": "texto_largo",
      "obligatorio": false, "ayuda": "Qué se plantea como salida." },
    { "name": "pedido_3p", "label": "Pedido (3P)", "tipo": "texto_largo",
      "obligatorio": true, "ayuda": "Qué se solicita concretamente." },
    { "name": "tematica_id", "label": "Temática", "tipo": "catalogo",
      "catalogo": "tematicas", "obligatorio": true },
    { "name": "estado_atencion", "label": "Estado de atención", "tipo": "catalogo",
      "catalogo": "estados_atencion", "obligatorio": false, "default": "Pendiente" },
    { "name": "documento_origen_id", "label": "Documento de origen", "tipo": "referencia",
      "entidad": "documento", "obligatorio": false }
  ],
  "reglas": ["3P mínimo: problema y pedido", "si viene de alerta, conservar alerta_id"],
  "ayudaGlosario": ["3p", "tipo_compromiso"]
}

Qué falta

  • Reunión: sin repositorio ni endpoint (item 72). La opción del menú existe, el formulario no puede guardar.
  • Capacidad por entidad: el modelo tiene privilegio_usuario y RLS, pero no una matriz explícita «rol × entidad × escritura» que el descriptor pueda leer; hay que definirla para que el menú no se codifique a mano.
  • 3P obligatorio: hoy el 100 % de las demandas tiene el 3P vacío; activar la validación sin datos previos obliga a decidir si se migran o se dejan incompletas.
  • Catálogo de estados de atención: no hay catálogo formal; el único valor es «Pendiente».
  • Aviso de duplicados (item 71): el descriptor necesita una regla de comparación por entidad antes de confirmar.

Decisiones de producto pendientes

  1. ¿El caso fijado se puede cambiar desde el panel o solo cerrándolo y abriéndolo desde otra ficha?
  2. ¿El selector de alerta de origen se limita a las alertas del caso o permite cualquier alerta del ámbito?
  3. ¿Los formularios heredan la ayuda del glosario (item 7) y de la ayuda navegable (item 9) desde el mismo descriptor?
  4. ¿Qué pasa con un registro iniciado al cambiar de vista? ¿Se conserva como borrador o se descarta?
