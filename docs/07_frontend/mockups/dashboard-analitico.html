Todas las cifras de esta pantalla provienen de una consulta de solo lectura a la base de AVISA del 22.11.2026. No hay series, promedios ni porcentajes estimados. Las consultas se listan para que el equipo pueda reproducirlas.

Casos: totales, estado, nivel, riesgo y prioridad 
SELECT ec.codigo AS estado, count(*)
  FROM core.casos c
  JOIN core.cat_estados_caso ec ON ec.id = c.estado_id
 WHERE c.anulado_en IS NULL
 GROUP BY 1;

SELECT nc.nombre AS nivel, nr.codigo AS riesgo, pa.codigo AS prioridad,
       count(*)
  FROM core.casos c
  JOIN core.cat_niveles_conflicto nc ON nc.id = c.nivel_conflicto_id
  JOIN core.cat_niveles_riesgo    nr ON nr.id = c.nivel_riesgo_id
  JOIN core.cat_prioridades_atencion pa ON pa.id = c.prioridad_id
 WHERE c.anulado_en IS NULL
 GROUP BY 1, 2, 3;
Desglose regional por riesgo 
SELECT r.nombre AS region,
       count(DISTINCT c.id) FILTER (WHERE nr.codigo = 'Alto')     AS alto,
       count(DISTINCT c.id) FILTER (WHERE nr.codigo = 'Moderado') AS moderado,
       count(DISTINCT c.id) FILTER (WHERE nr.codigo = 'Bajo')     AS bajo,
       count(DISTINCT c.id)                                       AS total
  FROM core.casos c
  JOIN core.caso_regiones cr ON cr.caso_id = c.id
  JOIN core.regiones r       ON r.id = cr.region_id
  JOIN core.cat_niveles_riesgo nr ON nr.id = c.nivel_riesgo_id
 WHERE c.anulado_en IS NULL
 GROUP BY 1
 ORDER BY total DESC, 1;

Primera respuesta: por qué no se grafica 
SELECT count(DISTINCT caso_id)              AS casos_con_hechos,
       count(*)                             AS hechos,
       round(avg(primer - fecha_inicio), 1) AS promedio_dias
  FROM (
    SELECT c.id, c.fecha_inicio,
           (SELECT min(k.fecha_evento)
              FROM core.caso_cronologia k
             WHERE k.caso_id = c.id AND k.anulado_en IS NULL) AS primer
      FROM core.casos c
     WHERE c.anulado_en IS NULL AND c.fecha_inicio IS NOT NULL
  ) q
 WHERE primer IS NOT NULL;
-- 5 casos con hechos (80 hechos). promedio_dias = -74.2
-- deltas negativos: fechas del legado anteriores a fecha_inicio.

Notas para el equipo que implemente

  1. Esto es un mockup estático: no existe ruta en la SPA ni endpoint de agregados. Los números son un snapshot real del 22.11.2026 y en la implementación deben llegar por API, nunca cablearse en el cliente.
  2. Item 51 (biblioteca de gráficos accesible): aquí se dibujan barras CSS y una serie SVG para no atar el mockup a un CDN. En producción se reemplazan por los componentes de gráficos del proyecto (Recharts u equivalente) con role="img", resumen accesible y tabla de datos alternativa —como ya se incluye aquí—.
  3. Item 52 (Resumen de Dirección): el desglose regional es real, la fuente es enlazable y la hoja de impresión se compone aparte de window.print(). Falta decidir qué variantes del módulo se muestran y con qué agregaciones.
  4. Item 57 (series temporales y sincronización): solo existe una serie anual de alertas. No hay SLA histórico, aging ni «última sincronización» global; tampoco una zona horaria declarada. El mockup no los simula. La zona de referencia institucional es America/Lima: requiere que cada timestamp del origen la declare (o guarde timestamptz) antes de calcular vencimientos, SLA o cortes diarios.
  5. Item 85 (Panel OAIPCS): carga, nivel/riesgo, señales sin caso y cobertura salen de datos reales. «Compromisos vencidos» y «tiempo de primera respuesta» quedan en estado vacío honesto porque el dato no existe.
  6. Filtros: Región y Riesgo recalculan la tabla y las barras regionales con los agregados disponibles. El snapshot no tiene el cruce caso a caso de todas las dimensiones, así que no se ofrecen filtros que prometan intersecciones que la consulta no puede resolver; en producción los cuatro filtros viajan al endpoint de agregados.

Qué falta para implementarlo de verdad

  • Biblioteca de gráficos accesible integrada en la SPA, con tabla alternativa y navegación por teclado.
  • Endpoint de agregados (por ejemplo GET /api/v1/analitica/resumen) que reciba región, nivel, riesgo, prioridad y rango temporal, y devuelva la métrica con su fecha de corte.
  • Definición de cada métrica firmada por OAIPCS: qué cuenta «cobertura», qué es una «señal sin triage» y cómo se mide la «primera respuesta».
  • Serie temporal instrumentada: registrar el evento de respuesta, la validación de alertas y la sincronización por fuente, con zona horaria explícita.

Qué no debe hacerse

  • No derivar la prioridad de atención del riesgo ni pintarla como conclusión: son escalas distintas y la Guía no define la regla de prioridad. El mockup muestra el valor almacenado.
  • No inventar tendencias ni completar años sin registros, ni tratar 2026 como año cerrado. Tampoco convertir conteos de registros en tasas o porcentajes de conflictividad.
  • No graficar cifras fijas en el cliente: si el endpoint falla, la tarjeta debe mostrar error/vacío con fuente y corte, no un número de respaldo.
