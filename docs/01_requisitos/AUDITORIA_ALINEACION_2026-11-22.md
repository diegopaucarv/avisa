## 0 · Reglas del barrido (obligatorias)

1. **Cirugía, no reescritura.** Se corrige la etiqueta, el valor enumerado, el estado o el hecho
   desactualizado. No se reescriben párrafos, no se resumen secciones, no se reordenan tablas.
2. **Mirar el contexto antes de tocar.** «Alto», «Bajo», «Medio», «Otros» y «Tercero» son también
   español corriente: sólo se corrigen cuando nombran un **valor de catálogo**, una **etiqueta de
   campo** o un **ítem de una enumeración cerrada**.
3. **No se cambian cifras, citas `archivo:línea`, códigos de caso ni tablas de datos.** Si una cifra
   parece incorrecta, se anota en el informe del bloque; no se «arregla» a mano.
4. **Dos capas, dos registros.** Los documentos de migración (`04_migracion/`, `05_datos/`) describen
   el legado y el destino: conservan el **valor legado junto al canónico** (`Archivado` → se
   documenta como `Atendidas`; `En_ejecucion` → `En ejecución`). Los documentos de requisitos,
   arquitectura y frontend usan **sólo el valor canónico**.
5. **Lo decidido no es lo implementado.** Si una decisión de producto está tomada pero su
   implementación no existe todavía, se escribe como _decidido, pendiente de implementación_ y se
   cita el artefacto que falta. Nunca se declara hecho lo que no está en la base o en el código.
6. **No se inventan datos.** Un hueco se anota; no se rellena.
7. **No se toca** nada de: `docs/avisa_actual/`, `docs/_archivo/`, `docs/img/`, `docs/casos_uso/*.puml`,
   `docs/*.sql`, `docs/05_datos/DICCIONARIO_DATOS.md`, `docs/05_datos/diccionario_datos.csv`,
   `docs/03_ejecucion/mvp_prioridad_tablas.csv` (artefactos generados), ni código
   (`app/`, `lib/`, `components/`, `angular/`, `migration/`).
8. **Cada edición se registra** en `/tmp/auditoria_docs/<bloque>.md` con el formato
   `archivo:línea · antes → después · respaldo`. El resumen va a §4 de este documento.
